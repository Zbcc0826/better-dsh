# 经验编译设计

日期：2026-11-19。依据 [SkillCompiler](https://arxiv.org/abs/2610.39508)（Compile Away Uncertainty, arXiv:2610.39508）和现有摩擦驱动插件。

## 要解决的事

插件现在只处理用得不顺的工具：失败、同参重试、截断过线之后，经用户同意，增加一个本会话的替代工具。用得顺、而且同一段调用已经反复成功的情况，模型仍会每次重新推理。论文指出，这种文本程序每次执行都会重新解释，结果不稳定；能写清输入、步骤和验收的操作应该变成可验证的程序，依赖上下文的操作继续留给模型。已验证的程序应被复用，而不是再生成一遍。

两件事都保留，都只在用户同意后生效，都可能多花 token。

## 更名与说明

面向用户的名字改为「经验编译」，英文 Experience Compiler。包名 `dsh-experience-compiler`。技能名 `experience-compiler`。新工具前缀 `ec_`。安装地址仍是 `github:Zbcc0826/dsh-friction-drive`，避免已验证的第三方安装入口失效。卡片标题、技能、README 和工具说明不再使用「摩擦驱动」作为产品名。

说明提供中英两份：`README.md` 与 `README.en.md`，以及 `locale/zh.json`、`locale/en.json`。开头都写明：行为来自 Agent 自己的使用体验；替代工具或沉淀程序在执行前征求同意；可能增加 token 消耗。

## 与论文的对应和刻意收窄

论文有五块：任务分解、可执行性判断、混合骨架、程序资产复用、失败后只重编受影响的步骤。本插件不另叫一个模型来做开放式任务分析。可观察的证据只有本会话里已经发生的工具调用。模型可以提议合同，插件用记录下来的调用验收，不接受没有发生过的步骤。

资产库只属于当前会话。换一个会话不会自动拿到上次的程序。论文的跨任务库在这里会绕过「每次同意只影响当前会话」。同一会话里，后一次沉淀必须先检索已验证程序。

检索不用模糊词面相似度。签名相同才算同一个程序。多个程序都配得上时不自动挑，退回给模型选择。这样避免把别的命令编译进来。

## 什么叫成熟的固定连续动作

插件在每次工具成功返回后记录一条：工具名、参数、是否成功、时间。成功的定义与现有失败判定相反：不是 `isError`，退出码不是非零，也没有 `failed: true`。本插件自己的工具不记入序列。

连续指中间没有别的工具调用，也没有失败。从成功轨迹里取长度 2 到 6 的连续片段。同一签名至少完整成功两次，才叫成熟。签名由这些部分组成：

- 工具名顺序
- 每个参数要么两次完全相同，记为常量
- 要么两次都在、JSON 类型相同、值不同，记为槽位
- 某个参数一次缺失，整段不成熟

过线的那次调用照常返回结果。插件把这段写入 `friction_status.compilable`，并在技能里要求模型提议沉淀。此时还没有新工具，也不拦截原调用。

## 混合程序

模型调用新的 `propose_compiled_procedure`。参数是一段合同，不是自由散文：

- `operations`：每步有 `id`、`tool`、`mode`（`program` 或 `agent`）、输入、输出名、前置条件、后置验收、给模型的短说明
- `order`：执行顺序，必须和观察到的工具顺序一致
- `edges`：上一步输出绑到下一步输入；没有数据依赖就可以只有顺序
- `slots`：槽位名必须来自观察到的变化参数
- `constants`：必须等于观察到的常量
- 程序步的 `run` 只能是委托原工具并覆盖常量，或一条带 `{{槽位}}` 的脚本。脚本只在被替代的工具就是 `bash` 时才绕过 bash 的门槛

`program` 步必须同时满足：输入输出写得明确、步骤就是上述 `run`、前置条件能从本会话环境看出、后置验收能独立检查、现有工具接口够用。缺任何一条，插件拒绝，不把它降级成悄悄的模型步骤。`agent` 步不执行，只出现在结果的 `remaining` 里。

插件自己重放两次已观察到的参数绑定。每一步的验收不过，提议在审批卡之前被拒绝，资产也不入库。重放使用与正式执行相同的委托或脚本，并绕过门槛，避免把验收调用再记成新的摩擦。

同一会话里按签名检索资产：

- 零个匹配：验证通过后，这是新资产
- 恰好一个匹配：提议必须引用该资产。再写一份不同脚本会被拒绝
- 多个匹配：返回 `AMBIGUOUS`，不自动执行

审批沿用一次性允许。卡片一行写清将要跑的脚本或覆盖值、常量、槽位，以及哪些步留给模型。无界面的命令行得到 `NOT_APPROVED`，不挂起。

同意之后注册 `ec_序列摘要_首次同意时间`。修订不改名，时间戳仍是首次同意时间。同内容修订拒绝。修订和恢复都沿用现有规则：本轮仍跑旧程序，轮次结束后才换上；可以退回上一版。

同意之后，下一次以同一签名的第一步直接调用原工具时，插件拒绝，并指向 `ec_` 工具和 `friction_status` 的说明。原工具定义不变。别的会话看不到这个工具。

`ec_` 工具只暴露槽位。执行时按顺序跑程序步，绑定常量、槽位和上一步输出，检查验收。任一步失败就停止并返回失败步骤。`remaining` 列出未执行的模型步。程序步失败计入该 `ec_` 工具自己的摩擦；过线后走现有的替代工具路径，不另写一套。

## 不做什么

不修改 bash、grep 等原工具的定义。不在已经发出的调用上改参数。不把资产写进共享的 `SKILL.md`。不按词面相似度自动合并两段不同命令。不在没观察到的轨迹上接受模型编造的步骤。

## 验收

单元测试覆盖：两次成功才成熟、中间失败或夹杂别的工具不算、常量与槽位划分、缺参数不算、重放失败拒绝、唯一资产必须复用、多资产不自动选、无审批不安装、安装后拦截序列起点、`ec_` 按槽位执行并在验收失败时停下、另一会话不可见、原有摩擦路径仍可用。
